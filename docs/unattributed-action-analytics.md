# 攻撃元不明の操作の分析（v3.8）

分析画面の「攻撃元不明の操作」で、選択期間の日次サマリ（日本時間0時区切り）、経路ランキング、直近200集計を確認できます。既存の認証・公開範囲の設定が適用されます。プレイヤー向けの追加通知やDiscordへの自動投稿はありません。

## 数え方

- 単位はガードが実際に拒否した操作数です。攻撃回数、攻撃者数、破壊予定ブロック数ではありません。無人機械の繰り返し試行や破片ごとの試行は都度数えます。
- 同一Explosionを複数のイベントリスナーが調べても1回です。他の独立した変更・損傷操作まで同じ攻撃と推定してまとめることはしません。
- 経路・ディメンションごとに1分間の件数をまとめます。時刻と座標は最初の代表値です。全発生地点の個別履歴ではありません。
- `game_event.type = provenance.rejected`、`detail = 経路`、`value = 拒否件数`。ランキングと日次集計は `SUM(value)` を使います。`COUNT(*)` は集計行数です。攻撃者・国家は推測せず空欄にします。
- 自然変化・モブ由来の処理、CBCの地形置換の全面禁止、平時の射撃保護は含みません。既存の領土・補強保護だけで止まった処理も含みません。

## 経路

| ID | 拒否した処理 |
| --- | --- |
| cbc.explosion / explosion | CBC系 / その他の爆発による地形・物体破壊 |
| cbc.direct_hit / cbc.autocannon_hit | CBC砲弾 / 機関砲弾の直撃による地形破壊 |
| cbc.projectile_event | CBCのブロック損傷イベント |
| cbc.partial_damage | CBCの部分損傷の蓄積 |
| warnautics.blast / warnautics.chip | Warnautics固有の爆風 / 破片処理 |
| level.replace / level.destroy | 発生源の実行文脈があるブロック置換 / ドロップ前の破壊 |
| event.place / event.break | 設置 / 破壊イベント |
| machine.break / remote.place | 機械による破壊 / 遠隔設置 |
| object.damage | 防具立て・額縁・乗り物・アイテム等への損傷 |
| piston.trigger / piston.event | ピストンの動作 / 移動イベント |
| dispenser | アイテム消費前のディスペンサー動作 |
| overflow | 1分の経路・ディメンション組合せが256種類を超えた分の合計 |

## ログとAPI

- サーバーログに `Unattributed action blocked` と経路・件数・ディメンション・代表座標・最初のUnix秒を1分単位で出します。分析停止時もログは出ます。
- `GET /api/provenance?window=7d` は既存のBearer認証で `days`、`routes`、`recent`、`analyticsRunning`、`droppedEvents` を返します。`days[].key` は日本時間の日付に対応するepoch day、件数は `total` です。
- 既存の `/api/events?type=provenance.rejected`、イベントCSV/JSONL出力も利用できます。汎用集計では `group_by=day` / `detail` を選べます。
- 日次サマリは保存済みイベントから集計するため、再起動後も残ります。保存期間は既存のgame_event保持設定に従います。日次ログの自動配信はありません。

## 運用上の限界

- メモリ上の集計は最大256キーとoverflowの1キーに制限し、既存の非同期キューへ送ります。overflowでは経路・ディメンションの詳細は失われますが合計件数は残ります。複数ディメンション混在なので、その代表座標で場所を特定できません。
- 反映には最大約1分に加え、既存の書き込み・クエリキャッシュの遅延があります。通常停止では残りを送信します。クラッシュでは直近のメモリ内集計や未保存イベントが失われることがあります。厳密な監査台帳ではありません。
- 過負荷では既存キューの欠落ポリシーに従います。画面の欠落数はキュー全体の累計であり、拒否操作数ではありません。0以外なら集計が不完全な可能性があります。分析停止中はログのみで、後からDBへ再投入されません。
- 計測対象は既存ガードが拒否した経路です。発生源文脈のない任意のMOD処理やチャンクへの直接書き込みを新たに検出・封鎖する仕組みではありません。

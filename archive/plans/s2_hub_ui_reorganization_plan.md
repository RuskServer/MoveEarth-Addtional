# S2 Hub 表示・操作導線の再整理計画

## 1. 目的と範囲

国家Hubを「機能一覧」から「現在の状況と、次にできる操作が分かる入口」へ整理する。
既存の /pvp 系 MoveEarthUi の色・カード・ボタン・半透明パネルを継承する。
大きな左サイドバーは追加せず、本文の面積を確保する。

国家・Siege・捕虜・維持費のルールや権限は変えない。履帯など並行作業には触れない。

## 0. 実装状況（2026-09-24）

- 5分類と二段目サブナビ、通信ID互換レイヤー、ページ別スクロール保持を実装済み。
- ホーム、国内（領土・財政・国民・役職）、外交（関係・講和/停戦）、
  戦争（Siege・捕虜・復興）、地方への再配置を実装済み。
- 混在していたSiege/講和/停戦/捕虜リストを分離し、既存の詳細画面と操作を維持。
- 全招待の切替、国民のオンライン絞り込み、応答タイムアウト、基本キーボード移動、
  日英表示、320×180を含むレスポンシブ領域計算を実装済み。
- 自動テストとassembleに加え、最終的な文字切れ・視認性は実機で確認する。

## 2. 現状確認

調査対象: S2HubScreen、S2HubOverviewLayout、S2HubTab、S2NationSnapshot。

- S2HubScreen は1,221行で、各画面の描画・入力・通信・確認ダイアログを持つ。
- 現行は「概要・メンバー・役職・外交・Siege・地方」の6タブ。
- 幅不足時はタブ名が1〜6の数字へ置き換わり、ホバーしないと意味が分からない。
- 概要は4枚の数値カード、Siege状態、領土プレビュー・財政・復興・金庫指定・
  設定または脱退の5ボタンを同じ領域へ表示する。
- S2HubOverviewLayout は下部ボタンの重なりを回避しているが、本文の固定Y座標は残る。
  画面が低い場合、数値カードと下部操作の必要高さが競合する。
- Siegeタブは講和提案・停戦・捕虜・進行中Siegeを同じリストへ表示する。
- 無所属時は多くのタブで同じ建国案内になる。招待は先頭1件だけ表示される。
- snapshot更新時にサーバー指定タブをそのまま採用し、scrollOffsetは画面全体で1つ。
- 地方は所属に関係なく閲覧でき、無所属でも個人Siegeを表示する特例がある。
  この導線は整理後も維持する。

## 3. 情報構造

上位分類は5つ。設定はヘッダー右端の独立した入口へ移す。
アイコンは補助とし、通常時は日本語ラベルを表示する。数字のみのタブは廃止する。

| 上位分類 | 内部構成 | 主な内容 |
| --- | --- | --- |
| ホーム | なし | 国家状態・要対応事項・よく使う入口 |
| 国内 | 領土 / 財政 / 国民 / 役職 | 領土プレビュー、金庫設定、国庫、参加申請、招待、役職 |
| 外交 | 関係 / 講和・停戦 | 同盟・敵対関係、受信/送信提案、停戦期限 |
| 戦争 | Siege / 捕虜 / 復興 | 戦争一覧、選択した戦争の詳細、捕虜・復興画面への入口 |
| 地方 | なし | 現在地方、特産・不足・他地方資源 |

### ホーム

1. 国家名・タグ・自分の役職をヘッダーに集約。所有者名などの詳細は国内へ。
2. 要対応事項は「進行中の戦争」「受信講和」など確認済みデータから作る。
   最優先1件＋残り件数を表示し、専用一覧または該当タブへ移動できるようにする。
3. オンライン/総国民、領土チャンク、稼働コア、維持費をコンパクトな指標欄にする。
   意味の近い情報だけをまとめ、数値だけでなく単位を明記する。
4. よく使う入口は原則3つまで（領土を見る・財政を見る・国民を見る）。
5. 平時は中立色。戦争がないのに大きな赤いカードを常設しない。
6. 金庫変更・脱退・降伏・国家設定をホームの主操作列に置かない。

概念配置（広幅。実装時の固定ピクセル指定ではない）:

```text
┌ 国家名 [タグ] ・自分の役職             更新  設定  × ┐
│ ホーム    国内    外交    戦争    地方                │
├───────────────────────────────────────────────────┤
│ 要対応: ○○とのSiege進行中              詳細を見る   │
│ 国民 5/12   領土 32ch   稼働コア 2   維持費 …      │
│                                                   │
│ [領土を見る]    [財政を見る]    [国民を見る]         │
│                                                   │
│ その他の対応事項 / 状態の短い説明                   │
├───────────────────────────────────────────────────┤
│ 更新状態 / 操作結果                                │
└───────────────────────────────────────────────────┘
```

### 国内

- 領土: 現在の領土/コア数とプレビューへの入口。詳細一覧を出す場合は取得APIを別途確認。
  現snapshotの数値から存在しないコア詳細を推測しない。
- 財政: 維持費・金庫指定状況の要約と NationTreasuryScreen への入口。
  「国庫残高/支払い」と「金庫保護チャンク指定」を別の見出しで説明する。
- 国民: 一覧・検索・オンライン絞り込み。管理者向け申請/招待は上部の操作行へ。
- 役職: 権限の概要と編集入口。行に全権限文を詰めず、選択時に詳細を表示する。
- 一般国民には閲覧可能な情報を残す。できない操作は権限不足の理由を提示する。

### 外交・戦争

- 外交関係、講和提案、停戦を別リストへ。受信・送信の区別と期限を明示する。
- 戦争の既定表示は進行中Siege。捕虜や停戦で戦況が下へ押し出されないようにする。
- 一覧は相手・攻守・段階・残り時間の要約に絞り、選択した戦争の詳細で操作する。
- 広幅では一覧＋詳細、狭幅では一覧→詳細の遷移。詳細から戻ると選択/スクロールを復元。
- 講和・撤退・降伏は対象と結果が読める詳細画面へ。降伏は別枠＋確認ダイアログ。
- 捕虜は PrisonerScreen、復興は RecoveryDispatchScreen を再利用する。
  同じ詳細や操作をHubにも重複実装しない。戻り先情報だけ統一する。
- 戦争から講和作成へは相手を引き継いで直接開けるようにし、分類移動の手間を増やさない。
- サーバーが持つ時間の意味を維持する。表示更新のために別の実時間カウントへ変えない。

### 無所属と個人操作

- ホームは「国家へ参加」「国家を建てる」の2経路を並列に案内し、建国だけを推さない。
- 招待は全件到達可能な一覧にする。既存の承認待ち/申請状態の表示可否と取得経路を確認する。
- 既存オンボーディング画面を通常参加者が開けるか確認し、未対応なら参加先一覧への
  安全な専用入口を用意する。初回スポーン拘束処理を誤って再実行しない。
- 国内は所属が必要な理由と参加入口を表示。地方はそのまま利用可能。
- 個人Siege・自身の捕虜状態など、無所属で必要な戦争導線を隠さない。
- 設定入口は所有者には国家設定、一般国民には所属情報と脱退確認を提供する。
  サーバー管理者の権限/例外は現在のサーバー判定と一致させる。

## 4. レイアウト・操作の共通規則

- GUIの論理解像度を使い、パネルは常に画面内へ収める。
- 広幅は最大760程度を初期案に、内容幅540未満では1列へ切り替える。
  数値は試作で調整し、固定の最小幅・高さが画面サイズを超える作りにはしない。
- ヘッダー/上位タブ/結果欄と、スクロールする本文を分離する。
- 低い画面では本文全体をスクロール可能にし、固定Y座標でカードを押し込まない。
- 上位タブは狭幅で折返す。収まらないラベルは意味のある短縮名＋ツールチップとし、
  数字だけや色だけで分類を表さない。本文高さは実際のタブ行数から計算する。
- 長い国家名・役職名は省略＋全文ツールチップ。重要な操作説明は折返す。
- アイコン/状態ラベルを併用し、赤だけで警告を表さない。
- 描画とクリック判定は同一のレイアウト結果を使う。スクロール領域外のクリックを無効化。
- Tab/Shift+Tab、Enter/Space、Escを整備する。最初のEscはモーダルを閉じる。
  既存描画スタイルを使い、フォーカス/読み上げ可能な操作部品として実装する。
- SuppressesChatOverlay の契約を維持する。単なる位置移動でチャット描画問題を回避しない。
- 処理中は該当操作を無効化して連打を防ぐ。結果は安定した結果欄で表示し、失敗理由を読めるようにする。
- 待機・未取得・空一覧・権限不足・失敗を別状態にする。取得前に「0件」と表示しない。
- 危険な操作の確認中は背面を操作できない。承認ボタンに対象国家/人物名を添える。

## 5. 通信と状態管理

- Hubの選択状態は client側の HubSection/Subpage として保持する。
  S2HubTab は既存通信ID 0〜5を維持し、見た目の分類と分離する。
- 対応: OVERVIEW→ホーム、MEMBERS→国内/国民、ROLES→国内/役職、
  DIPLOMACY→外交/関係、SIEGE→戦争/Siege、REGION→地方。
- 新設の国内/領土・財政や戦争/捕虜・復興は既存snapshotと既存画面要求を利用する。
- 通常のsnapshot更新はデータだけを更新し、ユーザーの選択を勝手に戻さない。
  明示的な画面遷移応答・対象国家変更・所属変更は別扱いにする。
- 選択ID・スクロール・検索語はページごとに保持。対象消失時だけ安全に解除。
- 外部画面から戻るための軽量なHubNavigationStateを保持し、古いScreen自体を永続保存しない。
- リクエストIDと応答の対応、タイムアウト表示を整理する。タイムアウト時は操作結果不明として
  再取得を促し、支払い/降伏などの変更要求を自動再送しない。
- UIで操作を隠すことを認可の代わりにしない。全操作のサーバー権限検証を維持する。

## 6. 既存データでできる範囲と追加取得

最初はsnapshot内にある国民数・領土数・コア数・維持費・金庫指定状態・Siege・講和・
停戦・捕虜・役職・外交・招待から構成する。戦争判定をsiegeStatusの表示文字列解析に依存させない。

申請未処理件数、未読通知数、正確な支払い猶予、国庫残高、コア個別一覧、復興の進捗は
現Hub snapshotだけで確実に表示できるとは限らない。既存詳細画面のAPIを調査し、
初期版は入口だけでも成立させる。未取得値を0や問題なしとして表示しない。
集約取得が必要なら別段階で追加し、個人/国家ごとの閲覧権限と負荷・互換性を確認する。

## 7. コード構成案

client/s2hub 配下へ段階的に分離する（実装時に既存参照先を追従）。

- S2HubScreen: 画面ライフサイクル、描画と入力の委譲。
- HubNavigationState: 分類/画面内タブ/戻り先/選択/スクロール。
- HubLayout: サイズから領域を計算する純粋なレイアウト処理。
- HubViewModel: snapshotから表示用の行・指標・警告を生成する。
- pages/: Home、Domestic、Diplomacy、War、Region。
- widgets/: 状態表示、一覧行、詳細パネル、操作欄、確認ダイアログ。

新しい汎用UIフレームワークは作らない。MoveEarthUiを再利用し、関連のない画面を一括移動しない。

## 8. 実装順序

1. **基盤・ホーム**: 全既存操作の移行先一覧を作成。レイアウト/状態を分離し、5分類と
   コンパクトなホームを実装。旧6タブにあった操作をこの段階でも全て到達可能に保つ。
2. **国内・設定**: 国民/役職の整理、財政・金庫の分離、脱退/設定の移設、無所属の参加導線。
3. **外交・戦争**: 混在リストを分割し、戦争詳細、捕虜/復興の戻り導線、危険操作の確認を統一。
4. **仕上げ**: 地方の折返し、検索/絞り込み、フォーカス・読み上げ、空/待機/エラー表示、
   タイムアウト、日英翻訳を整備。必要なら追加データ取得を別途実装。

各段階で対象テストとassemble。旧画面を削除する前に機能対応表を確認する。
コミット/pushは別途依頼時のみ。

## 9. 完了条件

- 建国・参加/招待承認拒否・国民招待/追放・役職作成編集割当・外交操作・講和・撤退・降伏・
  捕虜・復興・財政・金庫・領土プレビュー・脱退/設定・地方の入口が欠落しない。
- 確認画面を除き、ホームから主要画面へ2クリック以内を目標にする。
- GUI論理解像度320×180、426×240、640×360、960×540で操作が画面外へ逃げず、重ならない。
- 長い日本語/英語名、空/1件/100件一覧、無所属/一般国民/各管理権限/所有者/管理者、
  平時/複数Siege/講和受信/停戦/捕虜/復興を確認する。
- snapshot更新、一覧縮小、権限変更、画面再開で選択/スクロール/確認対象が破綻しない。
- 通信遅延・失敗・応答順逆転・連打で誤操作を起こさない。
- 単体テスト: レイアウトの内包/重なり/クリップ、旧ID対応、権限別表示、状態復元、警告優先順位。
- 実機確認: GUIスケール変更、チャット開閉、キーボード操作、子画面からの復帰、読みやすさ。
  assemble成功を視覚的な検証の代わりにしない。
